## Key integrity defects and limits

- Some inspected read paths now propagate database errors instead of returning fabricated empty/sample rows. Controller/service coverage is not exhaustive. Audit insert failures now reach the application logger, but those writes remain best-effort after some committed mutations and are not durable/atomic with them.
- Executive Super Admin report endpoints return HTTP 503 until real aggregate queries are implemented.
- Student creation no longer fabricates a result after failed persistence, but user creation and student profile creation are not one atomic workflow.
- Tenant-scoped controllers reject missing college scope in reviewed modules; a route-by-route tenant matrix and live cross-college database tests remain outstanding.
- Results are mounted under /exams/results/... and events under /notices/events/...; API documentation lists the mounted paths.
- Schema foreign keys do not replace application validation that related records belong to the acting user’s college or department.
- Company and internship catalog tables have no tenant key, so their operations are global in the current schema.
- Schema SQL drops and recreates tables. It is not a migration and must not be applied to a database containing data that must be preserved.

## Test safety

Existing Jest integration suites import the configured database pool and contain write operations. No isolated test database is configured and verified; do not run them against the current database.
